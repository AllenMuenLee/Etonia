# Study mistake memory

- Archive every graded incorrect or partially correct test question, including unanswered questions, with the original question, answer, grading feedback, test title, question number, course and grading date. Correct and ungraded questions do not create mistakes. Instant-feedback quizzes archive on feedback; exam quizzes archive only at submission.
- Persist history separately from editable papers and practice sets, serialize mutations, deduplicate unchanged mistakes and backfill existing graded papers. Preserve snapshots across resetting, answering correctly later, replacing or deleting practice material, and restarting. Propagate unreadable history rather than overwriting it.
- Apply memory to every Study Desk question, including retries, starters, suggestions, conversations without notes and graded-paper review. Leave the editor assistant independent. Keep historical data out of the visible user question and never treat it as instructions or note citations.
- Retrieve at most eight distinct past questions within a bounded text budget; prioritize question/error vocabulary, then course and recency, retaining fallback candidates for paraphrases. Retrieval produces candidates, not confirmed semantic matches. Reserve their bytes before assembling note or paper context.
- The answering model must determine whether a candidate is effectively the same question or demonstrates a particular misconception that can cause the same error on the current question. Topic or keyword overlap alone does not justify a reminder. If uncertain or unrelated, say nothing about history. A blank answer establishes no misconception. Do not infer reasoning from a wrong option alone.
- When relevant, briefly mention the prior test, date and question number, explain the particular trap constructively, then answer normally. Avoid unsolicited quizzes, repeated reminders in one answer and revealing solutions to unanswered active assessment questions.
- Verify extraction, partial credit, blank answers, ungraded exam selections, legacy backfill, deduplication, concurrent saves, restart/reset/deletion retention, unreadable-file preservation, bounded Unicode context, and request integration for normal chat, retries and review. Semantic relevance is model-driven; automated request tests cannot certify real-model judgment.
